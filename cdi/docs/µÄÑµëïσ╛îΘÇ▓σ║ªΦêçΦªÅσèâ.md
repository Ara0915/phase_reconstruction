## 〇、一分鐘進入狀況

**專案狀態**:診斷鏈已走完,缺口鎖定在**空間結構資訊**。

```
Oracle 控制    → 架構容量足夠(2.065 px 逼近 Nyquist 2.0),但網路在背答案
換訓練資料      → 訓練分布大幅改善,跨分布仍 0/4
多樣性曲線      → 推進至 5 萬種相異物體仍未飽和,但跨分布始終 0/4
加 HIO 迭代     → 跨分布首次轉正 1/4
過取樣重新設計  → 補絕對尺度有效,補空間結構無效
參數隨機化平反  → 全距縮小 18%,原「隨機化有害」結論撤回
                      ↓
              剩餘缺口 = 空間結構資訊 → 指向 ptychography
```

**但**:上次進度報告後,指導教授指出理論定位有誤,核心論述已改寫:

> 原本:「單張繞射圖的量測資訊不足」 → **不正確**
> (二維相位回復理論上唯一,Bruck & Sodin 1979;Hayes 1982)
>
> 修正後:**「解在理論上唯一,但在本專案的量測條件下逆映射不穩定」**

**這條承重論述目前只有間接支持(w_dc、HIO、Oracle),從未直接檢驗。**
→ 這就是接下來要做的事。

### 1.2 新增:階段四實驗設計協定

**八個風險點,每一條都對應日誌裡一個真實發生過、且產生過被撤回結論的錯誤。**

最重要的一項是**日誌尚未涵蓋的**:

> **⚠️ Oracle 的診斷邏輯在有探針之後會失效**
>
> Oracle 的全部診斷力量來自「任務即 $\mathcal F^{-1}$,線性、有封閉解、與物體外觀無關」。
> 但引入探針後:
>
> ```
> 完整複數場 → F⁻¹ → 出射波 ψ = P·O     ← 仍是線性良態
> 出射波 ψ   → ÷P  → 物體 O              ← 探針邊緣 |P|→0,病態
> ```
>
> 若階段四重跑 Oracle 而達不到理論極限,「架構容量不足」與「探針除法病態」
> 兩種解釋分不開。而 §13.7 正是以此作為重啟 attention 的判準 ——
> **這個混淆會錯誤地重開一條已排除的路線。**
>
> **解法**:同時報告 **Oracle-ψ**(目標為出射波,保留原診斷邏輯)
> 與 **Oracle-O**(目標為物體,量出探針除法的代價)。
> **attention 的判準必須用 Oracle-ψ。**

## 三、下一個動作:§1b.6 理想條件驗證

### 3.1 這個實驗在問什麼

把量測條件推到接近定理的理想假設,看**相位未知的正常路徑會不會大幅改善**。

| 結果 | 意義 | 後續 |
|---|---|---|
| **會改善** | 核心診斷坐實 | 階段四、五動機成立,照原計畫走 |
| **不改善** | **更有價值** —— 診斷是錯的,而且是在投入數週 ptychography **之前**發現 | 停下來重想 |

兩種結果都是好結果。這是設計良好的實驗的特徵,也是為什麼它該排第一。

**成本最低**:config-only,不用寫新程式;**最快能送**:今天就能丟進佇列。

### 3.2 ⚠️ 對 §1b.6 原始寫法的一項修正

日誌 §1b.6 原文寫「beamstop=0、劑量提高、**過取樣顯著提高**」三項一起推。
**本設計刻意把過取樣拆出去**,理由有二:

**(一)過取樣 2.29 並未違反定理,只是餘裕薄。**

| 定理假設 | 本專案 | 是否**違反** |
|---|---|---|
| 完整的傅立葉強度 | Beamstop 遮蔽中心 | ✅ **違反**(字面上缺資料) |
| 精確量測 | Poisson 雜訊 | ✅ **違反** |
| 充分過取樣 | 2.29 | ❌ **未違反** —— 門檻是 2,已滿足 |
| 實數非負物體 | 複數物體 | ✅ 違反(無法在不改變問題的前提下移除) |

**(二)過取樣對主指標的作用方向與假設相反。**

§12.3 實測:過取樣率 2.29 → 4.57 時 FRC gain **0.1400 → 0.1147(變差)**。

三項綁在一起推,可能出現 beamstop+劑量帶來改善、過取樣帶來惡化,
**互相抵消、FRC gain 看似沒動** → 誤判為「理想條件也沒用」
—— **在本專案最重要的實驗上產生假陰性。**

→ 過取樣改列獨立的第三臂(4-0c)。

### 3.3 實驗矩陣(4-0a 篩選,9 jobs)

訓練來源:程序生成。各組 3 seeds。

| 設定 | `beamstop_r` | `photons_per_pix` | `oracle_phase` | 用途 |
|---|---|---|---|---|
| `ideal_base` | 3 | 1,000 | false | 現況基準 **+ 重現性檢查** |
| `ideal_bs0_ph1e5` | **0** | **100,000** | false | **主臂** |
| `ideal_bs0_ph1e5_oracle` | **0** | **100,000** | **true** | 該條件下的天花板 |

**已用 `Cfg.load` 程式驗證變因控制:**

```
✅ ideal_base vs ideal_bs0_ph1e5         只差 beamstop_r、photons_per_pix
✅ ideal_bs0_ph1e5 vs ideal_bs0_ph1e5_oracle 只差 oracle_phase
✅ ideal_base 的訓練設定與 v2_proc 完全相同(只多 eval 欄位,不影響訓練)
```

**劑量取值的依據**(由 §假設 1 的實測反推,不是隨便挑):

$$\text{現況 } N_{\text{Nyquist}} = 88.6 \Rightarrow \frac{1}{\sqrt{88.6}} = 10.6\%$$
$$\text{本組 } k=100 \Rightarrow N = 8{,}860 \Rightarrow \frac{1}{\sqrt{8860}} = \mathbf{1.06\%}$$

相對雜訊降一個數量級。取 100 倍(而非精確達 1% 的 112.9 倍)是為了讓
log 平移量恰為 $\ln(100) = 4.605$,方便做正規化常數的數值斷言。

> **須註明**:100,000 光子/px 在真實實驗中並不現實,且本模型未含偵測器飽和。
> 這是**刻意的理想化** —— 逼近定理的理想假設,不是模擬可實現的實驗。報告時須明講。

**額外收穫:2×2 交叉評估矩陣**

用現成的 `eval_photons` / `eval_beamstops` 機制,順手把**待辦 2
(輸入正規化對劑量偏移的敏感度)**一起量了,而且劑量差 **100 倍**
(§12b.4 當時只有 3 倍)。等於順手關掉一個 open question。

⚠️ **但離開主場的格子帶有 §12b.4 的正規化假影,不可解讀為物理效應。**

### 3.4 程式碼查核結果(送出前已逐條確認)

原本最擔心的兩個地雷 —— **都已經修好了**:

| 原本的擔憂 | 查核結果 |
|---|---|
| `eval.py` 是否用各組自己的物理條件評估(§8.1 / §12b.1 **踩過兩次**) | ✅ **已修**。`eval.py:51` 讀該 run 的 `config_used.json`,`bs_mask` 與 `photons` 皆來自其自身設定 |
| 正規化常數是否在新劑量下重新校正(§12b.4) | ✅ **已修**。`train.py:72` 在 `log_mean is None` 時呼叫 `calibrate_input_norm`,後者用該 run 的 `cfg.photons_per_pix` |
| `config_used.json` 是否在校正後才寫出 | ✅ `train.py` 先校正、再 dump |
| `beamstop_r: 0.0` 是否支援 | ✅ `bs00.yaml` 已用過 |

**但煙霧測試仍須跑** —— `photons_per_pix = 100000` **從未跑過**
(既有最高是 `dose_1e4` 的 10,000),中心像素期望光子數會由 7,720 → 772,000。

### 3.5 判讀準則(事先寫定)

**主判準**:`ideal_bs0_ph1e5` 相對 `ideal_base` 的 FRC gain 改善幅度,
以及 `ideal_bs0_ph1e5` 與 `ideal_bs0_ph1e5_oracle` 之間落差的收斂程度。

現況條件下的落差已知約 **+0.08**(`v2_proc` ~0.21 vs `v2_proc_oracle` 0.2924)。

| 結果 | 解讀 | 後續 |
|---|---|---|
| 大幅改善 + 落差顯著收斂 | **核心診斷坐實** | 進階段四 |
| 小幅改善 | 部分成立 | 跑 4-0b 歸因 |
| 幾乎沒改善 | **診斷可能是錯的** | **停下來重想** |

**事先聲明**:若主判準顯示無改善,這是有價值的負面結果,
**不應以「換個指標再看看」處理**。§12b 的教訓是評估方式要先修對,
但修對之後就照結果報告。
