## 〇、對 §1b.6 原始寫法的一項修正(重要)

日誌 §1b.6 原文:

> 設 beamstop 為 0、劑量提高至雜訊可忽略、**過取樣顯著提高**,
> 觀察正常路徑(相位未知)能否大幅改善。

**建議把「過取樣」從主臂拆出來,理由有二:**

### 理由一:過取樣並未違反定理,只是餘裕薄

回看 §1b.3 的四項偏離:

| 定理假設 | 本專案 | 是否**違反** |
|---|---|---|
| 完整的傅立葉強度 | Beamstop 遮蔽中心 | ✅ **違反** —— 字面上缺少資料 |
| 精確量測 | Poisson 光子計數雜訊 | ✅ **違反** |
| 充分過取樣 | 2.29 | ❌ **未違反** —— 門檻是 2,已滿足,只是餘裕薄 |
| 多數結果針對實數非負物體 | 複數物體 | ✅ 違反(但無法在不改變問題的前提下移除) |

**過取樣 2.29 已經高於唯一性門檻 2。** 它影響的是條件數(穩定性),不是唯一性本身,
屬於二階效應;而 beamstop 與雜訊是一階的、字面上的違反。

### 理由二:過取樣對主指標的作用方向與假設相反

§12.3 已經量過,**而且方向是相反的**:

| 過取樣率 | FRC gain | 材料贏基準 |
|---|---|---|
| 2.29 | 0.1400 | 4.2% |
| 4.57 | **0.1147 ↓** | **15.3% ↑** |

**提高過取樣率會使 FRC gain 變差。**

若把三個變因綁在一起推,可能出現:beamstop 與劑量帶來改善、
過取樣帶來惡化,**兩者互相抵消,FRC gain 看起來幾乎沒動**,
於是誤判為「理想條件下也沒改善 → 診斷是錯的」。

**這是在本專案最重要的實驗上產生假陰性。**

### 修正後的設計

| 臂 | 內容 |
|---|---|
| **主臂(4-0a)** | 只移除**兩項真正的違反**:beamstop = 0、劑量提高 |
| **歸因(4-0b)** | 主臂若有效,再逐一分離 beamstop / 劑量 |
| **第三臂(4-0c,可選)** | 在理想條件之上**額外**提高過取樣,獨立檢驗餘裕的作用 |

附帶好處:主臂 canvas 維持 64,**不需要動 dilation、沒有感受野涵蓋率問題、
job 也跑得快**(canvas 128 的像素數是 4 倍)。

有了同條件下的 oracle,才能看**落差有沒有收斂** —— 這是最強形式的陽性結果。

## 二、劑量取值的依據

不是隨便挑的數字,是從 §假設 1 的實測反推:

**現況**(`photons_per_pix` = 1,000):

$$N_{\text{Nyquist}} = 88.6 \text{ 光子/px} \quad\Rightarrow\quad \frac{1}{\sqrt{88.6}} = 10.6\%$$

**目標**:Nyquist 附近的相對 Poisson 雜訊降至約 **1%**

$$\frac{1}{\sqrt{N}} = 0.01 \quad\Rightarrow\quad N = 10{,}000 \quad\Rightarrow\quad k = \frac{10{,}000}{88.6} = 112.9$$

**取整為 $k = 100$**($\texttt{photons\_per\_pix} = 100{,}000$):

$$N_{\text{Nyquist}} = 8{,}860 \quad\Rightarrow\quad \frac{1}{\sqrt{8860}} = \mathbf{1.06\%}$$

**相對雜訊由 10.6% 降至 1.06%,整整一個數量級。**

> **須註明**:100,000 光子/px 在真實實驗中並不現實(且本模型未含偵測器飽和,見附錄 C)。
> 這是**刻意的理想化** —— 目的是逼近定理的理想假設,不是模擬可實現的實驗。
> 報告時須明講此點。

## 三、送出前的檢查清單(Pre-flight)

> **這一節比實驗矩陣更重要。** 每一條都對應日誌裡已經真實發生過的錯誤。

### ⚠️ 檢查 1:`eval.py` 是否用**各組自己的**物理條件評估

**這是最大的地雷,而且這一類錯誤已經發生過兩次。**

| 事件 | 後果 |
|---|---|
| §8.1 | `eval.py` 測試集寫死 MNIST → `src_proc` 被誤判為訓練失敗 |
| §12b.1 | `eval.py` **完全沒有隨機化程式碼** → 結論已撤回 |

本實驗中,**每一組的訓練物理條件都不同**。
若 `eval.py` 用寫死的條件(bs=3、ph=1000)評估 `ideal_bs0_ph1e5`,
等於**拿理想條件訓練出來的模型,去考現況條件的題目** ——
結果必然很差,而且會被誤讀為「理想條件沒用」。

**✅ 已查核 —— 這個問題已經修好了。**

`eval.py:51` 以 `Cfg.from_dict(json.load(open(run/"config_used.json")))` 讀回
該 run 自己的設定;`bs_mask = beamstop_mask(cfg)` 與 `forward_measure` 內的
`photons = cfg.photons_per_pix` 皆來自其中。§8.1 的寫死問題在原始碼註解裡
也有明確記錄與修正。

另 `eval.py:120-126` 的 robustness 區塊會以 `beamstop_mask(cfg, radius=br)`
重建遮罩、並把 `photons=ph` 傳入 `evaluate`,故 `eval_photons` /
`eval_beamstops` 的掃描是真的生效的(§12b.1 的問題亦已修)。

### ⚠️ 檢查 2:正規化常數是否在新條件下重新校正

劑量提高 100 倍時:

$$\log(1 + 100 \cdot \text{counts}) \approx \log(1+\text{counts}) + \log 100$$

**整個輸入被平移約 4.6。** §12b.4 已證實劑量只變 **3 倍**
就足以讓 `rob_fixed` 的表現不升反降。這裡是 100 倍。

若 `log_mean` / `log_std` 沿用舊值,`ideal_bs0_ph1e5` 會因為**純粹的正規化問題**而表現很差
—— 又是一個假陰性。

**✅ 已查核 —— 程式會自動處理。**

`train.py:72` 在 `cfg.input_norm == "global" and cfg.log_mean is None` 時呼叫
`calibrate_input_norm(cal, bs_cal, cfg)`;後者(`physics.py:181`)以
`forward_measure(objects, bs_mask, cfg, photons=None)` 取樣,`photons=None`
會落回 `cfg.photons_per_pix`,**即該 run 自己的劑量**。
YAML 未手寫 `log_mean`(欄位註明「由程式填入,不要手寫」),故必定重算。
`config_used.json` 在校正**之後**才 dump(`train.py:78`)。

**仍保留數值斷言作為保險**(已寫進 `smoke_ideal_conditions.sh` 與
`check_ideal_conditions.py`):
- `ideal_bs0_ph1e5` 的 `log_mean` 應比 `ideal_base` **高約 4.6**(= ln 100);
  兩者相同 = 沒重算,停下來
- `ref_energy` 三組應一致(它只由物體決定,與劑量無關)

## 七、重現性參考值(已定,以實測為準)

`check_ideal_conditions.py` 頂端:**`V2_PROC_FRC_GAIN = 0.2106`**,容忍 **±0.02**。

### 實測值(2026-09-23,於計算節點讀 `v2_proc_s*/metrics.json`)

| seed | FRC gain |
|---|---|
| s0 | 0.2150 |
| s1 | 0.2170 |
| s2 | 0.1999 |
| **平均 ± 標準差** | **0.2106 ± 0.0093** |

先前由研究日誌推得的 0.2115(`hio2_net` 迭代 0 / `div20000` / `rob_fixed` 主場格,
三者訓練設定皆與 `v2_proc` 逐欄相同)與實測只差 0.0009,推論方向正確。

### ⚠️ 撤回:容忍 0.01 的依據有誤

先前把「三組 3-seed **平均值**之間的全距 0.0013」當成 seed 波動,據此把容忍收緊到 0.01。
但**單一 seed 的標準差是 0.0093**,平均值之間的全距小是因為平均已經壓掉了波動。

比較的是兩個「3 seeds 平均」之差,其標準誤為

$$\frac{0.0093}{\sqrt 3}\times\sqrt 2 = 0.0076$$

| 容忍 | 約幾倍標準誤 | 純 seed 波動就誤報的機率 |
|---|---|---|
| 0.01 | 1.3 | 約 19% |
| **0.02** | **2.6** | **約 1%** |

### 對主判準的含意

同一標準誤也適用於各臂之間的比較:**兩臂平均相差小於約 0.02 時,無法與 seed 波動區分。**
現況下正常路徑與 oracle 的落差約 0.08,約為此門檻的 4 倍,故主判準仍有鑑別力;
但「小幅改善」若落在 0.02 以內,應判為**無法區分**,而非「部分成立」。

不採用 `rr_os64` 的 0.1392:該組 `match_support_to: null`(`v2_proc` 為 0.0318),
訓練分布不同,不是同一個基準。

`metrics.json` 的 `test` 欄位一律在該 run 自己的主場條件下評估
(`eval.py:84-87`,與 `eval_photons` / `eval_beamstops` 掃描無關),故可直接比對。

### 8.3 依事先寫定準則的判定

> **主判準:正常路徑改善 +0.0067,小於 0.02 門檻(z = 0.9)→ 無法與 seed 波動區分 → 視同無改善。**

**不可採用的讀法**:「落差由約 0.08 收斂至 0.067」。
(一)0.08 為跨批次數字;(二)收斂量中 0.009 來自 oracle 自身較 `v2_proc_oracle`(0.2924)低,
而非正常路徑上升。批次內乾淨的比較只有「主臂 vs 基準」一項。

### 8.4 已確立的事實(不含詮釋)

1. 拿掉 beamstop、相對雜訊 10.6% → 1.06%,正常路徑的 FRC gain 與材料 MAE **沒有可偵測的改善**。
2. 同一近理想量測下,給繞射相位仍帶來 +0.067 FRC gain、材料 MAE 由平庸基準降 26%(z ≥ 14)。
3. 故 beamstop 與 Poisson 雜訊**不是**正常路徑的主要限制。§一之二「在本專案的量測條件下逆映射不穩定」
   中,以「量測條件(beamstop、雜訊)」為原因的部分**未獲支持**。「解唯一」本身不受影響。

### 8.5 待檢驗的候選解釋(皆為假設,未驗證)

| 候選 | 支持 | 可檢驗方式 |
|---|---|---|
| **A. 資訊在量測裡,但前饋網路抽不出來**(學習/逼近問題) | HIO 在現況條件下即把 FRC gain 由 0.2115 拉到 0.3116(§11.3);近理想條件下 R-factor 反升,輸出與極精確的量測不一致 | 對 `ideal_bs0_ph1e5` 的 checkpoint 做 HIO 迭代掃描:若網路 + HIO 大幅超越網路本身並逼近 oracle,即支持 A |

## 十一、平凡歧異性檢查(§10.5 的檢驗)

腳本:`ambiguity_check.py`(計算節點互動執行,不重新訓練)。

### 11.1 做法

**① 歧異性在實際上存不存在**:對各方法的輸出,在
{原解, 共軛翻轉} × {所有循環平移} × {全域相位} 中找與真值最接近者,對齊後再評分。

| 對照 | 用途 |
|---|---|
| **錯配對齊**:把輸出對齊到「另一張」物體的真值 | 對齊本身能製造的分數(機率水準) |
| 隨機起點 0 次迭代 | 雜訊對齊後的分數 |
| 未對齊分數須重現 `hio_ideal.json` | 內建,差 > 0.005 即停 |
| 自我檢查:三種變換不改變繞射強度;對齊可還原已知變換 | 內建 |

**② 網路的模糊是否來自對等價解取平均**:振幅與其 180° 旋轉的相關(中心對稱度),
比較 真值 / 網路 / oracle。oracle 有繞射相位、沒有歧異,作為對照。
現況條件的 oracle 用 `v2_proc_oracle`(同訓練設定、不同批次)。

### 11.2 判讀準則

> ⚠️ **透明聲明**:本地測試(真實產生器 + 真實前向模型 + 真實 HIO,64 張、未訓練的假網路)
> 中,**純 HIO 那幾列不經過網路,等同真實結果的小樣本預覽**,已顯示對齊後大幅上升
> (理想條件 50 次迭代:未對齊 0.032 → 對齊 0.637,錯配 −0.063;翻轉約 50%)。
> 故 ① 的準則是**看過該預覽之後**才寫定的。② 的準則在任何相關數字出現前寫定。

**①(主)**:理想條件、純 HIO 5000 次

| 結果 | 解讀 |
|---|---|
| 對齊後 − 錯配對齊 > 0.10,且對齊後 ≥ 網路本身(0.217) | **歧異性確實存在,且 HIO 在近理想量測下其實解出了物體**,只差位置/方向 |
| 對齊後 ≈ 錯配對齊 | HIO 沒有解出物體,歧異性不是它失敗的原因 |

**①(輔)**
- 選翻轉比例接近 50% → 相位範圍約束 φ ∈ [0, φ_max] **沒有**打破共軛翻轉(§1.5 的宣稱不成立)
- 理想條件 網路 + HIO 5000 次對齊後 ≥ 200 次的 0.307 → §10.4 第 2 點的「越跑越差」是漂向等價解

**②**:網路 − oracle 的中心對稱度 > 0.05 且 z > 2 → 支持「網路對翻轉解取平均」是模糊的來源之一。
未達 → 歧異性存在但不是網路模糊的主因(網路可能已靠「物體置中」的先驗解決平移,並靠 A–φ 相關解決翻轉)。

4. 網路本身對齊後只多 +0.016,平移中位 0 px:**網路沒有擺錯位置,而是模糊**。

### 12.4 ② 的限制

網路的中心對稱度(0.41)遠高於真值(0.075),也高於 oracle(0.27)。
但**模糊本身就會讓置中的物體更接近中心對稱**,oracle 也比真值對稱許多即為此故。
網路比 oracle 更模糊,故 ② 的差距**不能完全歸因於對翻轉解取平均**。
② 與「網路對等價解取平均」**一致,但不是乾淨的證明**。
較乾淨的檢驗:比較網路輸出與「真值和其翻轉的平均」的相似度,對照「真值模糊到同解析度」。

## 十五、平凡歧異性不變的訓練目標(`amb_base`)

### 15.2 設計

  選擇不回傳梯度;資料一致性項本就對等價解不變。
- 3 seeds;對照組 `ideal_base` 已有,不重跑。
- **首次修改既有程式**:`src/config.py`(新增兩欄,預設關閉)、`src/losses.py`(新增 `align_target`)、
  `train.py`(多記錄兩欄)。已測:預設路徑下 loss 與原版**逐位元相同**;
  等價解的振幅/相位 loss 為 0;原 loss 對同一批等價解給出大 loss(amp 0.357、phase 0.673)。
- 安裝以 `amb_update/install_amb.sh` 進行:比對國網現有檔案與原始版本的 md5,一致才覆蓋,並先備份。

**已知限制**:訓練初期網路輸出近乎均勻,對齊的選擇近乎隨機(本地測試初期選翻轉約 0.35–0.47、有平移約 0.97),

## 十九、架構比較(oracle,理想條件):內建轉換 vs attention

### 19.1 設計

三組皆為理想條件的 oracle,訓練設定逐欄相同,**只差 `arch`**(程式驗證):

| 組 | arch | 參數量 | 說明 |
|---|---|---|---|
| `ideal_bs0_ph1e5_oracle` | unet | 1,928,738 | 已有 |
| `arch_fft_oracle` | fft | 1,940,718(+0.6%) | 偵測器端小網路(3 層卷積)→ **固定反傅立葉轉換** → 原 U-Net |
| `arch_attn_oracle` | attn | 2,965,922(**+54%**) | 原 U-Net + 編碼器 16×16、8×8 兩層各一個 self-attention 區塊 |

**fft 的細節**:繞射振幅不經學習,直接由輸入通道 0 反推 `sqrt(counts / scale)`(與 `forward_measure`、`hio.py` 同尺度);
偵測器端網路只估每個頻率的相位(K = 4 個假設,以 cos / sin 分量正規化成單位複數)與 beamstop 內的振幅;
`psi_k = IFFT(A · e^{iθ_k})`(與前向模型嚴格互逆),K 個複數場的實部與虛部共 8 通道送入原 U-Net。
已測:無雜訊、無遮罩下以真實相位代入,固定轉換還原物體的最大誤差 6e-7。

**attn 的細節**:標準 pre-norm transformer 區塊(LayerNorm → 4-head attention → 殘差 → LayerNorm → MLP(4 倍寬)→ 殘差),
**可學習的絕對位置編碼**(反傅立葉轉換的權重取決於絕對頻率位置)。只放在 16×16 與 8×8 兩層,
因 attention 計算量隨位置數平方成長(全解析度 4096 個位置)。

**程式修改**:`src/model.py`(新增兩個類別,`build_model` 依 `arch` 分派)、`src/config.py`(新增 `arch`、`fft_k`、`attn_heads`)。
已測:`arch=unet` 時模型與原版**逐位元相同**(參數與輸出)。安裝以 `arch_update/install_arch.sh` 比對 md5 後進行。

**參考線**:
- **直接反轉**:量測振幅 × 真實繞射相位 → 反傅立葉轉換 → 套 support 方框(不學任何東西的 oracle)。
- 純 HIO 5000(取自 `oracle_proto.json`)。

**已知混淆**:attn 多了 54% 參數。若 attn 有效,需另做參數量對齊的對照才能歸因於 attention 本身。

### 20.1 oracle 各原型 FRC gain(理想條件,對齊後,3 seeds)

| 原型 | U-Net | **內建轉換(fft)** | attention | 直接反轉(不學) | 純 HIO 5000 |

### 20.2 依 §19.2 判定

| 架構 | polygon / bandpass | 判定 |
|---|---|---|
| fft | 0.792 / 0.757(皆 ≥ 0.50) | ✅ 通過;lattice 0.726 > U-Net 0.594 |
| attention | 0.117 / 0.041(皆 < 0.20) | ❌ 與 U-Net 同樣失敗(多 54% 參數,改善 < 0.01) |

### 20.3 解讀

1. **瓶頸確實是「頻率空間 → 實空間」的轉換**:把轉換交給程式後,oracle 由 0.29 直接到達物理上限
   (與不學任何東西的直接反轉相同,FRC 0.766 vs 0.765),材料 MAE 更優於直接反轉(0.009 vs 0.026;
   網路學會補 DC 像素與去雜訊)。
2. **attention 沒有學會轉換**:具全域視野、參數多 54%,在 polygon / bandpass 上仍與 U-Net 相同。
   在本資料量與訓練預算下,「讓網路自己學全域轉換」這條路不成立。
3. fft 三個 seed 的 FRC 到小數第四位相同:任務在給定相位後近乎平凡,三者收斂到同一解並觸及上限。
   其末段 loss 降幅 2.9%(看似未收斂)是因為 loss 已接近雜訊底線(0.014),相對降幅被放大;FRC 已在上限,無再提升空間。

### 20.4 ⚠️ 限制:這是 oracle,成功在意料之中

給了真實相位時,內建轉換的輸出**本身就已經接近答案**。本實驗證明的是「障礙在轉換、且內建轉換可解決」,
**不代表**相位未知時也會成功。相位未知時,偵測器端的小網路必須自己估每個頻率的相位 ——
相位是全域資訊,3 層局部卷積幾乎不可能單獨估出來。第 2 步才是真正的考驗。

### 23.2 方法(同一批 512 張、同一份量測,3 seeds)

量測與 `realign_eval.py` 完全相同(`ideal_base_s{0,1,2}`,`torch.manual_seed(test_seed + s)` 後第一次抽樣),

| 代號 | 內容 | 角色 |
|---|---|---|

| **B** | A + shrinkwrap + ER 收尾,隨機起點 | 實務標準做法,公平基準候選 |
| **D** | A,但起點為 U-Net(`ideal_base`)輸出 | 參考 |

迭代次數:5、10、20、50、100、200、500、1000、5000,另加 ① 的同時間點。

**shrinkwrap 參數**(Marchesini 等 2003;實作寫在新檔 `src/hio_sw.py`,`hio.py` 不動):

- **門檻 4%**(非該文的 20%),依據如下

**門檻的決定(只用真值、不看重建,且用與測試集不同 seed 的 1024 張校準集):**
規則:「由**完美重建**(真值)算出的 support 必須幾乎完整包住物體」—— 否則真值不再是固定點,
shrinkwrap 會把正確答案切掉。要求各 σ 階段平均涵蓋率 ≥ 99.9%。

  GPU 上小運算的單張時間強烈依賴 batch 大小,**兩者不可直接比**。
- 本次在同一程序中、同一 GPU,以**相同 batch** 量 HIO(A、B)與三個網路(`amb_base`、`arch_fft_amb`、`arch_unroll_amb` 的 s0):

### 23.4 判讀準則

記 F_X(n) 為方法 X 在 n 次的對齊後 FRC gain(3 seeds 平均);N_q(X) 為格點中第一個使 F_X ≥ q 的 n。

**① 同時間的目標線**(batch 64):報告 A、B 在 n_eq(U-Net)、n_eq(unroll) 的分數。

(不可只挑較弱的一版比。)

**② 需要幾輪**:取實務可行者(A 或 B)中較早達標者的 N_0.35。

| N_0.35 | 解讀 | 下一步 |
|---|---|---|
| ≤ 50 | 幾十次就夠 | 展開 v2:輪數增至約 N_0.35,各輪共用修正網路(訓練成本約為現版 10 倍以內) |

| > 500 或未達 | 增加輪數不可行 | 先做階段四(探針),再回頭設計展開 |

**③ support 是不是主要障礙**(S\* vs A,看 n ∈ {20, 50, 100, 200}):

| 結果 | 解讀 |
|---|---|
| 任一 n 上 F_S\* − F_A ≥ 0.10 且 z > 2 | **support 資訊是主要障礙** → 展開 v2 應讓網路估 support;階段四的探針(照明範圍即已知 support)動機增強 |
| 所有 n 上差距 ≤ 0.02 | support 不是障礙,難度在相位本身 → 回到 ② |
| 其他 | 部分成立 |

**④ 實務 shrinkwrap**(B vs A):任一 n ∈ {50, 100, 200, 500} 上 F_B − F_A ≥ 0.05 且 z > 2 → shrinkwrap 有效。
不論結果,之後的公平基準一律取 A、B 中較強者(見 ①)。**參數不因結果調整。**

### 24.4 確立的事實

1. **support 是 HIO 慢的主因。** 給真實 support,HIO 10 次即達 0.62、20 次 0.735、材料 MAE 0.061(A 同次數 0.283 / 0.318)。
   S\* 在 50 次達峰值(0.747、材料 0.038),之後隨迭代**下降**(5000 次 0.656 / 0.152):support 精確時,迭代過多會擬合 Poisson 雜訊。
2. **實務 shrinkwrap 只在大迭代數有效**:support 縮得很慢(200 次 976 px、5000 次 812 px;物體約 140 px),
   故 ≤ 100 次與 A 無差;5000 次時優於 A(0.718 vs 0.643,材料 0.059 vs 0.106),polygon 提升最多(0.38 → 0.63)。
   之後的公平基準:每個時間點取 A、B 中較強者。
3. **網路起點(D)只在前幾十次有幫助**:5 次 +0.249、20 次 +0.096、100 次起 ≈ 0。
4. **「網路比 HIO 快」取決於 batch 大小。** batch 64 時 U-Net 在同時間贏過 HIO(+0.089),batch 512 時輸(−0.128)。
   U-Net 的時間優勢來自 HIO 在小 batch 下受 GPU 啟動開銷限制,**不是穩健的優勢**,不宜單獨作為「網路有用」的主張。
5. **展開 HIO(5 輪,0.160 ms,0.199)被簡單組合全面壓過**:U-Net + 5 次 HIO 只需約 0.050 ms,即達 0.312。

### 24.5 解讀與限制

- **S\* 的資訊量很大**:真實 support 是物體的精確輪廓(含位置),本身就是答案的一大部分,且同時消除平移與翻轉歧異。
  故 ③ 證明的是「若能知道 support,問題幾乎解決」;**網路能否把 support 估得夠準,尚未檢驗**。
- 展開 v2 的時間成本:現版每輪(物理步驟 + 修正網路)約等於 HIO 10 次的時間。若 v2 用 20–50 輪,
  同時間的對手是 HIO 200–500 次(B:0.58–0.66),「有用」須達約 0.63–0.71 以上。
  只有在網路把 support 估到接近 S\* 的程度時(S\* 20–50 次為 0.73–0.75),才有機會。

(a) 真實 support 外擴 1 / 2 / 4 px;(b) 由既有 U-Net 輸出取門檻得到的 support(網路**現在**已知道多少 support)。

## 二十五、階段四 4-1:小探針能否提供 support?(HIO,不需訓練)

### 25.1 問題

§二十四:給 HIO 真實 support,10–20 次即解出;但本專案物體細而分散,大探針或放寬的 support 幾乎不提供範圍資訊(§24.7)。

### 25.2 設計(同一批 512 張、同一份量測,3 seeds)

- **劑量**:聚焦探針把同一道光集中,**每張繞射圖的總光子數與平面波相同**。
  以校準集(seed 2026)算出 ψ 與物體的平均能量比,乘到 `ref_energy`(不用測試集本身校準)。
- beamstop、雜訊模型、`hio.py` 的更新規則、β、對齊評分皆與 §二十四 相同;三種方法共用同一個隨機起點。

| **P** | 探針圓盤(實驗上已知) | **主角** |
| **S\*ψ** | ψ 的真實範圍(物體 ∩ 圓盤) | 上限(實驗上拿不到) |

### 25.5 本地測試中發現的數值問題(2026-09-24,只用真值)

寫固定點測試時發現:**約 0.08% 的物體像素振幅恰為 1**(`build_object` 的 clamp,12% 的樣本含此類像素),

- 處理:測試改把真值移到約束邊界內(振幅 ×0.95、相位移到 [0.05, 0.95]·φ_max)後,三種半徑 100 次最大差 ≤ 1.3e-6。
  `hio.py` 維持原行為不修改(與既有結果一致),同 §21.1。
- **對 §24.4 第 1 點的影響**:S\* 在 50 次後分數下降(0.747 → 0.656)原解讀為「擬合 Poisson 雜訊」;
  上述「邊界像素觸發負回饋」是**另一個候選解釋**,兩者尚未區分。

**劑量檢查第一版有誤(國網 `--check` 時發現,2026-09-24)**:第一版以**前 64 張**、**套 beamstop 後偵測到的**光子數比對,

- 修正:改為不套 beamstop、用完整 512 張;「偵測到的」比值另列參考。只改檢查,**量測本身與判讀準則不變**。
  真值估計(無雜訊)為 0.970 / 0.975 / 0.988。r8 實際偵測到的光子約少 5–8%,但三種方法共用同一份量測,不影響同一半徑內的比較。

### 26.4 解讀與限制(假設)

- P 與 S\*ψ 的剩餘差距(0.06–0.14):P 仍保留圓盤內的平移自由與完整的翻轉歧異。真實探針有像差、不對稱,
  **預期能打破翻轉**;可在 4-2 以不對稱探針檢驗。
- 平頂、無像差、單張不掃描(限制同 §25.6)。目標是被照亮的一小塊,**不與 §二十四(整個物體)的分數交叉比較**。
- 4-2 中網路要算「有用」的對手:**同時間的 P-HIO**(20 次約 0.38–0.46、50 次約 0.55–0.60),
  HIO 的迭代數須事先寫定(因 P 在約 100 次後會下降)。
