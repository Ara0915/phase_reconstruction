## 二十三、階段四 4-2a：平頂探針下訓練網路（v9，2026-09-24 / 25，結案）

完整的設計、事先寫定的準則與逐步數字見專案文件 `階段四實驗設計協定.md`（v2）§三、§四、§八。本章為摘要與結論。

### 23.1 問題與設計

4-1（§二十一）顯示已知的小探針範圍讓 HIO 快速解出被照亮的部分。4-2a 問：**網路能不能同樣用上這個資訊？能否在同樣時間內贏過知道探針範圍的 HIO？**

- 條件：程序生成資料、現況量測（beamstop 3、劑量 1e3）、平頂圓盤探針 r = 12 px（448 px）、重建目標為出射波 ψ = P·O；
  所有網路的輸出乘上探針圓盤，HIO 以圓盤為 support（P-HIO）；歧異性不變 loss 開啟；其餘同 `amb_base`。
- 組別（各 3 seeds）：`probe_unet`（U-Net）、`probe_unroll`（物理內嵌的展開 HIO）、`probe_unet_oracle`（給繞射相位，Oracle-ψ 上限）。
- 展開版的輪數與修正網路**依事先寫定的計時規則選定**（總時間 ≤ P-HIO 100 次，選輪數最多者）：**c16（4 層 3×3 卷積、16 通道）、每 2 輪修正一次、T = 50**（參數 170,937）。
- 判讀準則（結果出來前寫定）：
  - §4.1 用上探針資訊：F（訓練分布、對齊後 FRC gain）≥ 0.35；polygon、bandpass 各 ≥ 0.30 → 能處理非週期結構。
  - §4.2 有用（主判準）：對手 = **同時間內 P-HIO 的最佳值**；網路 − 對手 ≥ 0.05 且 z > 2（batch 64）；batch 512 也成立 → 穩健有用。
- 內建檢查：每個 run 的未對齊分數重現 `metrics.json`；P-HIO 重現 4-1（+0.6003 對 +0.6003）；新管線的 `hio()` 與 4-1 的 `hio_ext` 差 0；
  計時與迭代數線性（R² 1.0000）；`log_mean` 在探針條件下重新校正（5.3770 → 5.4109）。皆通過。

| ds | — | **分段反傳**：每 10 輪切斷梯度、每段計 loss 取平均；推論不變 | F **0.012**（≈ 機率水準） |
| （診斷） | ds 連內建的 HIO 都沒用上 | 修正量為 HIO 狀態的 **8–15 倍**，把 HIO 整個蓋掉；起點不是問題 | — |
| v3 | — | **未訓練時輸出 = 同起點的 HIO 50 次**：自然讀出 + 有界殘差、修正上限 0.1·tanh、分段改為每 5 輪 | 12% 的步出現 nan |
| v3b | nan | 三步診斷：**空樣本**（物體整個落在探針圓盤外）造成；訓練池排除空樣本 | F **0.5915** ≈ P-HIO 50 次；一個 seed 退化 → 訓練失敗 |
| v3c | 停損點 ②（事先約定只調一次） | 學習率 2e-3 → 1e-4（文獻值） | 關卡退化（−0.0215）→ **展開版先停** |

**梯度爆炸**（未訓練模型，64 張，一次反傳的總梯度範數；對照 U-Net 1.46）：

| 展開輪數 T | 2 | 4 | 6 | 10 | 20 | 30 | 50 |
|---|---|---|---|---|---|---|---|
| 總梯度範數 | 0.21 | 0.25 | 0.31 | 0.93 | 7.3e3 | 1.3e6 | **7.2e10** |

每輪約放大 1.6 倍，與前向實測「HIO 對微小差異每輪放大約 1.8 倍」一致。梯度集中在最前端（偵測器端網路、第 0 輪修正）。
梯度裁切只能防止 nan，無法使訓練有意義（裁切前範數約 1e10，每步都被裁）。

**ds 的診斷**（`diag_unroll.py`，不訓練，只做前向；第 50 輪，自然讀出 = hio.py 最後一步的讀法）：

| 情況（3 seeds） | 對齊後 F | \|修正\|/\|h\| |
|---|---|---|
| 模型本身（網路起點、修正開） | −0.007 | 8.1 |
| 同一起點、修正關 | **+0.565** | — |
| 隨機起點、修正關（= P-HIO，健全性檢查） | +0.594 | — |
| 隨機起點、修正開 | −0.006 | 14.7 |
| 未訓練模型的起點、修正關 | +0.586 | — |

依事先寫定的判讀：**修正網路破壞了 HIO**（關掉修正即恢復）；起點不是原因。訓練紀錄中 loss 自 epoch 1 起即停在約 0.50：
模型很早就走上「修正網路 + 輸出頭直接產生輸出、繞過 HIO」的捷徑，而這條路只有幾層小卷積、學不會全域轉換。
根本原因是**設計**：修正沒有大小限制，且輸出頭從隨機開始 —— 未訓練的模型輸出並不等於 HIO，保底不存在（見 23.6 與 §19.1 須註明）。

**v3 的分段長度**：改為自然讀出後，loss 直接經過 g 反傳穿過 HIO，初始化梯度在 K = 10 時為 20.6–109（ds 版的隨機輸出頭幾乎不依賴 g，
梯度 0.25 掩蓋了問題）。依事先寫定的規則（整除 50、兩個初始化皆 < 10 的最大 K）改為 **K = 5**（實測 0.83 / 1.18；國網 64 張 0.595）。

**空樣本的 nan**（三步診斷；判讀準則事先寫定）：
1. 40 批中壞 6 批（15%，與訓練紀錄的 13–16% 一致）；前向與 loss 皆有限，只有梯度非有限；每批只由 1 張樣本造成；float64 下仍壞。
   異常偵測指向 loss 的 sqrt —— **但可能是假線索**：預測強度恰為 0 時 sqrt 的反傳會先算出 nan、隨後被 clamp 的反傳遮掉，異常偵測遇到第一個 nan 就停。
2. 邊界法（保留每個中間張量的梯度，找「nan 的最下游」）找到一張**空樣本**。但此步有兩個疏失：`build_pool` 的物體會隨總數 n 改變，
   未重現第一步的批次；且單張跑時資料一致項的分母為 0（被 1e-12 下限放大 1e12 倍）。準備好的修法 `dc_eps` 在空樣本上使 loss 變成 4e11，已撤回。
3. 與第一步相同的訓練池、整批檢查：**壞批次 = 含空樣本的批次（6/6）**，拿掉空樣本後 6/6 恢復。空樣本的預測自第 4 段起恰為 0。
   GPU 上確切是 loss 中哪個運算對「預測、目標、光子數皆為 0」產生 nan，CPU 上無法重現；修法（`drop_empty`）不依賴確切運算。

空樣本的來源：物體位置在 64×64 畫布上隨機，探針固定在中央；訓練池約 0.12–0.15% 物體整個落在圓盤外（一批 128 張含至少一張的機率約 18%）。
物理上對應探針掃到樣品外的空白區，並非錯誤；只是不含可學的資訊。U-Net 的輸出恆 > 0，不受影響。

| 材料 MAE | 0.117 | P-HIO 50 次 0.149、100 次 0.110 |
| 未見分布 | 2/4 | P-HIO 100 次 4/4；U-Net 1/4 |
| 速度（ms/sample） | b1 18.7 / b64 0.306 / b512 0.153 | U-Net 0.98 / 0.029 / 0.023 |
| 同時間（僅供參考） | batch 64 = P-HIO 97 次（0.647），差 **−0.056**（z −5.0）；batch 512 差 −0.057 | — |

v3c（學習率 1e-4）關卡：訓練後 0.553、未訓練 0.575（−0.0215）→ 退化；loss 0.374 → 0.307（v3b 為 0.257）。

**解讀**
1. **v3b ≈ HIO 50 次**：訓練穩定、loss 明顯下降（0.36 → 0.26）、材料 MAE 改善（0.149 → 0.117），但 FRC 平均只 +0.003。
   學到的修正改善了逐點數值，沒有改善空間結構。
2. **同時間輸在額外成本**：25 次 c16 修正與讀出的時間約等於 47 次 HIO，而修正沒有帶來相當於 47 次 HIO 的進步（HIO 50 → 97 次：+0.056）。
3. 修正量常貼近上限（\|修正\|/\|h\| 1.37–1.50；seed 1 的相位殘差 0.097，上限 0.1）；降低學習率後修正變小（1.01），但反而退化。
4. 保底設計本身有效：v3b 能處理非週期結構（polygon 0.30、bandpass 0.67），U-Net 做不到 —— 但這是內建 HIO 的功勞。

### 23.5 4-2a 結論

依事先寫定的停損點（協定 §8.14）：**展開版先停，不再調整；主線進 4-2b 的 HIO 部分。**

> **在單張繞射圖、平頂探針（r = 12）的條件下，重建靠的是物理（HIO + 探針提供的 support）；網路目前加不了分。**
> - U-Net 用不上探針資訊（0.258），只在極短的時間預算內（batch 64）贏 HIO，不穩健。
> - 物理內嵌的展開網路最佳可做到「等於 HIO 50 次」，但學到的修正抵不上其計算成本，同時間輸給 P-HIO（−0.056）。
> - P-HIO 100 次 0.648、未見分布 4/4：**已知探針提供的 support 是真正起作用的資訊**（§二十一 在訓練實驗中再次確認）。

**這不是主線的失敗**：「網路能否用上資訊」的問題延到資訊更多的階段五（重疊掃描）再檢驗。
§22.4「更多資訊能否幫到網路」在 4-2a 的條件下答案為**否**；4-2b 的 HIO 部分與網路結果無關，照原規劃進行。

### 23.6 方法學教訓

| 教訓 | 發生在 | 以後的做法 |
|---|---|---|
| 「未訓練 = 原演算法」只驗證了內部狀態、且用隨機起點；模型實際的起點與輸出頭都是隨機的 | 首批、ds（亦見 §19.1） | 驗證**端到端的最終輸出**，用模型實際走的路徑 |
| 首批已出現「停在 0.50」，卻只當成梯度爆炸去修 | ds | **先診斷，再修**；診斷腳本可直接用失敗的 checkpoint |
| 修法只驗證了初始化時的梯度；本地短訓練規模太小 | ds | 修法須在訓練狀態下檢驗；吃算力的測試交由國網短跑或關卡 |
| 訓練失敗準則只抓 nan / 暴衝，抓不到「停在平庸解」 | ds | 加上「不得比未訓練（保底）差」的退化判定 |
| 異常偵測回報的第一個 nan 可能被後續運算遮掉 | nan 診斷 | 以「邊界法」（中間張量的梯度）定位 |
| `build_pool` 的內容隨總數 n 改變；單張重跑會改變批次層級的正規化 | nan 診斷 | 重現時用**完全相同**的池大小與批次，整批檢查 |
| 探針條件下沒檢查「圓盤內須有物體」 | 空樣本 | 新增變因時，檢查其每一種極端情況（含「完全沒照到」） |

這些教訓與文獻的標準原則一致（`文獻整理_展開網路與相位回復.md`）：展開網路應讓未訓練時重現原演算法（Monga, Li, Eldar）；
文獻中成功的展開多半是穩定的演算法、只學少量受限的參數（UPR、PRISTA-Net），學習率 1e-4 量級（HIONet 7e-5）；
HIONet 以學習的模組**取代** support 投影，而非在 HIO 之後另加修正。

### 23.7 數值註記

1. **`eval.py` 的量測雜訊未固定 seed**：輸出經過 HIO 的模型對雜訊的實現值敏感，重算分數與 `metrics.json` 可差約 0.05（本地 32 張）；
   評分腳本的載入檢查對展開版放寬為 0.05。所有方法之間的比較都在評分腳本內使用同一份量測，不受影響。
2. **測試集也含少數空樣本**（約 0.1%），前向不受影響，對所有方法相同。
3. **空樣本排除後仍有約 0.5% 的步非有限**（v3b 22–33 步），來源未查；未超過事先寫定的 1% 門檻。
4. U-Net / Oracle 的訓練池含 0.12% 空樣本，v3b / v3c 不含（`drop_empty`），未重訓 U-Net。
