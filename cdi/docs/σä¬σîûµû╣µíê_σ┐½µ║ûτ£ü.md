# 網路優化方案：更快、更準、訓練成本更低（2026-09-27 草稿）

> **目的**：在「以純網路為研究主體」的前提下，改良階段五確認有效的 DEF2 網路（B：U-Net；C：內建物理）。
> **現況（協定 §15.7，新測試場確認）**：B nerr 0.249、推論 0.082 / 0.068 ms（batch 64 / 512）、穩健有用；C nerr 0.177、0.142 / 0.124 ms、只在 batch 64 有用。
> 皆以 10 萬個場訓練，測試 / 訓練誤差比約 1.4（仍有過擬合）。
> **本文件**：一、文獻與相關領域的調查；二、可行方案（對應三個改進方向）；三、執行順序；四、評估紀律；五、停損點。

---

## 一、調查結果

### 1.1 更快

| 來源 | 做法 | 重點數字 | 對我們的意義 |
|---|---|---|---|
| PtychoNN 2.0（Babu et al., Nat. Commun. 2023） | 去掉振幅分支、濾波器數減半；TensorRT 部署 | 參數 4.7M → 0.7M；Jetson 上 PyTorch 14.8 ms → TensorRT 3.7 ms（約 4 倍）；A6000 上 70 μs / 張 | 同領域已證明「變小 + 推論引擎」可大幅加速，且品質仍與迭代法相當（SSIM > 90%） |
| 網路架構搜尋（DeepHyper，X-ray 應用，2024） | 自動搜尋 PtychoNN 的結構 | 參數 −13%、誤差 −17%、延遲 −9% | 自動搜尋的增益有限，成本高 → 不優先 |
| U-Net 知識蒸餾（Mangalam & Salzmann 2018） | 大 U-Net 當老師，教小 U-Net | 參數壓到 1/1000，指標只小幅下降 | 可讓「C 的準度」轉移到「B 的速度」 |
| 混合精度 / 推論引擎（NVIDIA、PyTorch 官方） | bf16 / fp16、TensorRT、torch.compile | 卷積在 tensor core 上常見 1.5–4 倍 | 純工程手段；需檢查精度，並注意公平性（§四） |

### 1.2 更準

| 來源 | 做法 | 重點數字 | 對我們的意義 |
|---|---|---|---|
| PtychoDV（Gan et al., IEEE TCI 2024） | ViT 從多張繞射圖產生初始影像 → **3 級展開**（Wirtinger 梯度步 + 小 CNN） | 稀疏取樣下 NRMSE 0.065，與最強迭代法 PMACE 相同，時間 0.074 s vs 34.9 s（約 500 倍快）；PtychoNN 類網路 0.48 | **最強的方向**：一個端到端訓練的網路，裡面放少數幾步物理修正（同 C 的「網路內建物理」精神） |
| PtychoPINN / PtychoPINN-torch（2023、2025） | 物理前向模型 + 重疊約束 + Poisson loss；CBAM 注意力；多探針條件化 | 2.8 萬張合成資料即可；比迭代法快 12–555 倍；作者坦言「解析度仍不及迭代法」 | 物理約束放進架構比放進 loss 更有效（與我們 D ≈ B、C 最準一致） |
| Fourier Imager Network（Chen et al., LSA 2022）、DPR（npj CM 2025，Fast Fourier Convolution） | 在網路中做全域傅立葉運算（全域感受野） | FIN 泛化優於遞迴 CNN；DPR 9 ms / 張、比迭代法快 > 1000 倍 | 與 C 的「內建 FFT」相同思路 → 支持持續發展 C |
| NAFNet（Chen et al., ECCV 2022） | 影像復原的簡化區塊（無非線性啟動、SimpleGate、LayerNorm） | 去模糊 SOTA 的計算量只要 8.4% | 可同時更快、更準的骨幹替代品 |
| PtychoFormer（2024） | 雙分支 Transformer | 比 PtychoNN 多 0.9 dB | 增益小、較慢 → 不優先 |

### 1.3 訓練成本更低

| 來源 | 做法 | 重點數字 | 對我們的意義 |
|---|---|---|---|
| 影像重建的 scaling law（Klug & Heckel, ICLR 2023） | 誤差隨資料量呈冪律下降，中等資料量後明顯趨緩 | 外推顯示百萬級資料幫助有限 | 我們 20k → 100k 誤差減半，還沒飽和，但報酬會遞減 → 要量曲線，不要盲目加 |
| 等變 / 對稱性（Celledoni et al. 2021 等） | 把旋轉、鏡射對稱放進網路或資料 | 提升品質與資料效率，推論不加成本 | 我們的物體與 DEF2 探針都有對稱性 → **免費的資料擴增** |
| 模擬資料即時產生（Holl & Thuerey 2024 等） | 每一步都產生新資料，沒有固定資料集 | 可避免過擬合 | 我們的瓶頸是 CPU 產生物體 → 用「隨機平移 + 旋轉 / 鏡射」在 GPU 上即時變出新場 |
| 混合精度訓練（PyTorch 官方） | bf16 自動混合精度 | 常見 1.5–3 倍 | 訓練時間直接下降，需確認準度不變 |
| PtychoNN 2.0 | 線上 / 持續訓練，cyclic LR | 10 萬對、8 張 A100 約 10 分鐘 | 同樣量級的資料在同領域是常態 |

## 二、可行方案

| 編號 | 方案 | 做法 | **更快** | **更準** | **更省** | 成本 |
|---|---|---|---|---|---|---|
| **P1** | 免費資料擴增 | 每個 batch 對已存的場做隨機循環平移 + 8 種旋轉 / 鏡射（在 GPU 上，之後才模擬量測，物理上一定正確）。平移完全不改變物體的分布；旋轉 / 鏡射假設產生器大致各向同性，執行前先檢查統計量 | | ✅ | ✅ | 低 |
| **P2** | 混合精度訓練 | bf16 autocast 訓練，評估仍用 fp32 | | | ✅ | 低 |
| **P3** | 學習曲線分析 | 讀現有 24 + 9 個網路的訓練紀錄，看 epoch 是否過多（不用跑） | | | ✅ | 零 |
| **P4** | C 輕量化（C-lite） | C 的「逐張估相位」小網路變窄（32 → 16 通道）、K 4 → 2，或在半解析度估相位 | ✅ | | | 中 |
| **P5** | 知識蒸餾 | 老師 = C（最準），學生 = B 大小或更小的 U-Net（base 16 / 24） | ✅ | ✅（學生） | | 中 |
| **P6** | 網路內建少數物理修正（PtychoDV 式） | C 或 B 的輸出 → 2–3 級「AP 重疊投影 + 小 CNN」，整個網路端到端訓練 | | ✅✅ | | 中到高 |
| **P7** | NAFNet 式骨幹 | 用 NAFNet 區塊取代 U-Net 的 DoubleConv | ✅ | ✅ | | 中 |
| P8 | 推論工程（輔助結果） | bf16 / channels_last / torch.compile / CUDA graph；迭代法也給同樣的工程優化 | ✅ | | | 低 |

**不建議（附理由）**：Transformer（PtychoFormer：增益小且慢）；測試時擴增（要推論 8 次，違背速度目標）；物理 loss（D 與 B 相同）；只把網路加大（會變慢，若要就配合 P5）。

## 三、建議的執行順序

### 第一輪：便宜、同時處理「更準」與「更省」

1. **P3 學習曲線**（零成本，先做）
2. **P1 + P2** 一起：B、C 各訓練 4 種（20k / 100k × 擴增有無），全部用 bf16 訓練；另以 B-100k 做一次 fp32 對照，確認 bf16 不影響準度
3. **P8 推論工程**：只作輔助紀錄

### 第二輪：架構，處理「更快」與「更準」

4. **P4 C-lite**（目標：C 的準度、B 的速度）
5. **P6 內建物理修正**（目標：大幅更準；最有希望讓純網路更接近迭代法的最終品質）
6. **P5 蒸餾**：以第二輪最準的網路當老師（若 P4 已達標可省略）
7. P7 視前面結果決定是否做

## 四、評估紀律（避免反覆看同一批測試資料）

- **驗證場**：新的 512 個場（物體 seed 80,000,000）—— 所有方案之間的比較與挑選都只看這批。
- **最終確認場**：另一批從未使用的 512 個場（seed 95,000,000）—— 只在優化全部結束時，用最終選定的網路跑**一次**。
- seed 90,000,000（§十五）已用過一次，不再使用。
- 每個方案在執行前寫定：比較對象、判定門檻、允許的調整次數。
- 對手的比較方式不變：包絡（§10.4）、同一 job 重新計時、嚴格 fp32 為主判。
- **P8 的推論工程為輔助結果**：只有在迭代法也得到同等工程優化（例：torch.compile、半精度 FFT 可用時）的情況下，才放進主判；否則分開報告。

## 五、停損點

### 5.1 每個方案

- 每個方案**一次**事先寫定的嘗試，最多加**一次**事先寫定的調整；未達門檻就放棄該方案。

### 5.2 各方向的「有效」門檻（相對目前 B / C，在驗證場上）

| 方向 | 有效 = |
|---|---|
| 更準 | 同速度（± 10%）下 nerr_ph **降低 ≥ 10%**（逐 seed 比值 ≤ 0.9、z < −2） |
| 更快 | 同準度（nerr 不高於 +3%）下推論時間 **≤ 0.83 倍**（快 ≥ 1.2 倍）；以 batch 64 為主判，batch 512 不得變慢 |
| 更省 | 同準度（+3% 以內）下訓練 GPU 時間 **≤ 0.8 倍**（同型 GPU 比較） |

> 2026-09-27 使用者調整（任何方案執行之前）：更快由 1.5 倍放寬為 **1.2 倍**、更省由 0.5 倍放寬為 **0.8 倍**。
> 理由：這些是「值不值得採用某個優化」的門檻，不是「網路是否贏過迭代法」的判準；後者（§10.4、§12.5 的包絡比較，比值 ≤ 0.8 且 z < −2）**不變**。
> 1.2 倍遠大於計時的量測波動（同一 job、5 次取中位數，歷次重測差異約 1–3%）。

### 5.2b 回報與採用（2026-09-27 使用者決定）

- 門檻是**回報時的參考**，不是自動的採用 / 淘汰規則。
- 每個方案**不論是否過門檻**，都回報改善程度：比值、z 值、三個 seed 的逐一數字、對速度 / 準度 / 訓練時間的影響，並標示「達門檻」或「未達門檻但有改善」或「無改善 / 變差」。
- **是否採用由使用者與 Claude 一起決定**；未達門檻但被採用的調整，須在文件中註明「未達事先門檻，討論後採用」與理由。
- 因為採用決定是看過驗證場結果後才做的，**最終結論只以最終確認場（seed 95,000,000，只跑一次）為準**。

### 5.3 整體停損

- **輪數**：最多兩輪（§三）。
- **計算量**：優化階段合計上限約 **80 GPU 小時**（`normal2`）。
- **停止條件**：兩輪結束，或達到計算量上限，或第一輪與第二輪**連續兩輪都沒有任何方向達到 §5.2 的門檻**（此時仍回報所有改善程度，由我們一起確認是否停止）→ 停止優化。
- **停止後**：凍結當時最好的網路（至少是目前的 B / C），在最終確認場（seed 95,000,000）上跑一次，然後**回到主線**：
  貼近真實條件（位置誤差、探針不確定、低劑量）→ 更大的掃描 → 階段六（晶格訓練集）。

## 六、P5–P7 的詳細做法與時間估計（2026-09-27，使用者表示優先考慮這三項）

### 共同的前置工作

| 項目 | 內容 | 時間 |
|---|---|---|
| 驗證場 | 新 512 個場（seed 80,000,000）；在上面跑一次迭代法的包絡（同 5-2b，只做 DEF2），之後所有方案共用 | 1 個 job，約 10 分鐘 |
| 預先計時 | 所有候選架構以未訓練的權重量推論時間（時間與權重無關）→ 先淘汰明顯太慢的設定，再決定要訓練哪些 | 同一個 job，約 5 分鐘 |
| 共用評估程式 | 讀任意列出的模型：驗證場 nerr、同 job 計時、vs 包絡、與 B / C 的比值 | 程式撰寫 |

### P5 知識蒸餾（更快、學生更準）

- **調整**：新增「老師」模式 —— 訓練學生時，每個 batch 讓老師（C-100k，之後可換成 P6 的最佳網路）以 eval 模式同時輸出；
  學生 loss = 0.5 · nerr(學生, 真值) + 0.5 · nerr(學生, 老師)（R0；比例事先寫定）。U-Net 寬度改成可調（base 16 / 24 / 32）。
- **研究手段**：學生 × {有 / 無蒸餾} 的對照 —— 蒸餾的效果 = 同一個學生「有蒸餾 vs 無蒸餾」；base 32 無蒸餾就是現有的 B。
  建議 3 組 × 3 seeds：base 32 + 蒸餾、base 16 + 蒸餾、base 16 無蒸餾（對照）；base 24 視預先計時決定。
- **風險**：模擬資料的真值是完美的，蒸餾的好處可能比文獻（真值稀缺）小；小網路在 batch 64、80 × 80 下可能受 kernel 啟動時間限制，變窄不一定等比例變快 → 由預先計時先確認。
- **時間**：程式 + 本地測試 + 審查約半天；國網 9 個網路 × 約 40–60 分鐘（含老師的額外前向，約 +30%）≈ 7 GPU 小時，同時 2 個 → 約 3.5–4 小時。

### P6 網路內建少數物理修正（PtychoDV 式，更準）

- **調整**：新架構 = 初始網路（B 或 C）→ K 級，每級：
  (1) **物理步**：一次 AP 重疊投影（9 張的量測振幅、已知探針與位置；與 AP-C 的一次迭代相同，可學的步長 ∈ (0, 1]）；
  (2) **小 CNN 修正**（殘差式，約 4 層、32 通道）；(3) 投影回物體約束。整個網路端到端訓練，loss 為各級 nerr 的平均（deep supervision）。
  以已訓練的 B / C 權重當初始網路的起點（warm start，縮短訓練）；加梯度裁切（階段四展開版曾出現 NaN，那次用的是 HIO 的負回饋，這次用較穩定的投影）。
- **仍是「純網路」**：級數固定、一次前向、整體訓練，時間全部計入網路（同 C 內建 FFT 的定位）；和「網路起點 + 迭代法」不同。
- **研究手段**：
  - P6-B：B + 3 級；P6-C：C + 2 級（級數依預先計時，讓總時間接近 C）。
  - **消融**：P6-B 拿掉物理步（只剩 CNN 級）→ 分辨改善來自物理還是只是參數變多。
  - 「只有物理步、沒有 CNN」= 網路起點 + AP-C 1–3 次，已在 5-3 / §十五量過，直接比較、不用訓練。
  - 共 3 組 × 3 seeds = 9 個網路。
- **風險**：訓練穩定性；每級約 +0.01–0.02 ms（AP 一次 0.0065 ms + 小 CNN），3 級後速度接近 C → 要比 C 準才划算。
- **時間**：程式最多（新模組、梯度檢查、數值穩定測試、本地測試、審查）約 1 天；國網 9 個網路 × 約 1–1.5 小時 ≈ 11 GPU 小時，約 5.5–6 小時。

### P7 NAFNet 式骨幹（更快或更準）

- **調整**：把 U-Net 的 DoubleConv 換成 NAFBlock（LayerNorm → 1×1 卷積 → 3×3 depthwise 卷積 → SimpleGate → 簡化通道注意力 → 1×1 卷積，殘差；
  再接 SimpleGate 的前饋部分）；下採樣用 stride-2 卷積、上採樣用 pixel shuffle；輸入、輸出與約束同 B。
- **研究手段**：NAF-B（參數量與 B 相同）、NAF-B-小（推論時間比 B 短約 20%，由預先計時決定寬度）；2 組 × 3 seeds = 6 個網路；
  優化器、學習率排程與 B 相同（公平比較）；允許的一次調整：改用 NAFNet 原論文的 AdamW + cosine。
- **風險**：depthwise 卷積在 GPU 上常受記憶體頻寬限制，小影像不一定比較快 → 預先計時先確認。
- **時間**：程式 + 本地測試 + 審查約半天到 1 天；國網 6 × 約 50 分鐘 ≈ 5 GPU 小時，約 2.5–3 小時。

**順序**：前置 → P6 與 P7 一起寫、一起送（互不相依）→ 看結果後做 P5，老師用當時最準的網路（C 或 P6）。

## 七、執行順序：P7 → P6 → P5 的漏斗式篩選（2026-09-27 使用者決定）

### 7.1 規則

```
前置（驗證場 + 預先計時）
   ↓
P7（NAFNet 式骨幹）── 有改善 → 採用，當作後面的基礎
   │                  沒改善 → 不採用，基礎維持 B / C
   ↓
P6（內建物理修正，建在「目前的基礎」上）── 有改善 → 採用
   │                                        沒改善 → 不採用
   ↓
P5（蒸餾）：老師 = 目前最準的網路；學生 = 目前最快的架構
   ↓
凍結最終網路 → 最終確認場（seed 95,000,000）考一次 → 回到主線
```

- 三步**都會做**；「改善與否」只決定下一步建在哪個網路上。
- P6 建在目前的基礎上：若 P7 有改善，P6 的初始網路與其中的小 CNN 使用 NAF 版本；否則用 B / C。
- P5 固定最後做：P6 讓網路更準（通常也更慢），P5 再把準度轉移到快的學生上 —— 兩者互補。

### 7.2 「有改善」的操作定義（每步結束時回報，並與使用者確認）

- 在驗證場上，該步的**目標方向**（P7：準或快；P6：準；P5：學生的準或快）有**統計上明確**的改善：逐 seed 比值 < 1 且 z < −2；
- 且其他方向**沒有明顯變差**：誤差不高於 +3%、推論時間不高於 +10%。**P6 例外**：以「更準」為目標，時間變長可接受，條件是在它**自己的推論時間下仍贏過迭代法的包絡**（比值 ≤ 0.8、z < −2；至少 batch 64，batch 512 一併回報）；
- 是否達 §5.2 的門檻照實標示；未達門檻但有改善者，依 §5.2b 討論後決定是否採用。

### 7.3 P5 的對照

學生架構若已有「無蒸餾」的訓練結果（例：B、或 P7 已訓練的 NAF-B 小），直接當對照；否則另訓練一組無蒸餾的學生。蒸餾的效果 = 同一個學生「有 / 無蒸餾」的比較。

### 7.4 停損

總計算量約 80 GPU 小時為上限；**P7 → P6 → P5 依序做完就結束優化**（使用者確認）。三步都沒有改善 → 凍結 B / C；有改善 → 凍結漏斗篩出的最佳網路。兩種情況都在最終確認場考一次，然後回到主線（貼近真實條件 → 更大的掃描 → 階段六）。
