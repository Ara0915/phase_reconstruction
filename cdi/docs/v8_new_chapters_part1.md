### 15.1 設計

§十四.4 顯示純 HIO 的輸出 97% 相對真值平移、49% 為共軛翻轉，未對齊的分數嚴重低估 HIO。

> ⚠️ **透明聲明**：本地測試中純 HIO 不經過網路，等同真實結果的小樣本預覽（A 4/4、C 吻合、D 的 lattice 增益最大）。

### 15.2 A：未見分布 —— 「0/4」是網路特有的問題

相對增益（dB，振幅 PSNR − 該分布平庸基準），5000 次，3 seeds：

| | mnist | fashion | shapes | texture | 贏過基準 |
|---|---|---|---|---|---|
| 網路本身（未對齊） | −4.06 | −2.02 | −2.88 | −4.53 | 0/4 |
| 純 HIO 對齊後 | +0.75 | +7.41 | +9.74 | +12.06 | **4/4** |
| 純 HIO 錯配對齊 | −2.98 | −2.40 | −1.62 | −2.88 | 0/4 |

網路 + HIO 對齊後，500 次起亦為 4/4（未對齊全程 0/4）。
**物理迭代與訓練分布無關，在四個未見分布上都贏過基準**；跨分布的「0/4」來自網路，不是量測。

### 15.3 B：MNIST 上 HIO 沒有破壞結果

| 迭代 | 網路 + HIO 未對齊 | 網路 + HIO 對齊 | 純 HIO 對齊 |

| 0 | 0.287 | 0.343 | −0.042 |
| 200 | 0.229 | 0.346 | 0.198 |
| 1000 | 0.152 | **0.354** | 0.227 |

MNIST 上**網路起點有實質貢獻**：網路 + HIO（0.354）> 純 HIO（0.227）；材料 MAE 網路本身 0.194 < 純 HIO 0.261。
與程序生成相反（那裡兩者對齊後幾乎相同）。

### 15.4 C、D：R-factor 停止準則成立；HIO 對 lattice 並非特別有效

**C**：兩種起點的 R-factor 最小點與對齊後 FRC 最佳點皆在 5000 次，R 選點為最佳值的 100%。
先前的不吻合完全是漂向等價解造成 → **§11.5 的限制撤回**。

**D**（對齊後 FRC gain / 材料 MAE，3 seeds）：

| 原型 | n | 網路本身 | 網路 + HIO 200 | 純 HIO 5000 | HIO 增益 |

| lattice | 204 | **0.502** / 0.286 | **0.660** / 0.094 | 0.646 / 0.117 | **+0.145（最小）** |
| bandpass | 206 | 0.019 / 0.344 | 0.560 / 0.206 | **0.734 / 0.076** | **+0.715** |

- **§12c.4 不成立**：lattice 的 HIO 增益最小，因為**網路本身在 lattice 上已經很好**。
- **新發現：網路的平均分數（約 0.22）幾乎全部來自 lattice**；在 polygon 與 bandpass 上網路 ≈ 平庸基準。

## 十六、歧異性不變的訓練目標（v8，2026-09-23）

### 16.1 問題與設計

網路在 polygon / bandpass 上 ≈ 平庸基準，且輸出含固定圖樣。**網路學不會，是否因為被迫猜一個猜不到的位置與方向？**

- `amb_base` 與 `ideal_base` **只差 `amb_invariant: true`**（程式驗證）。
- loss 計算前，把真值換成與網路輸出最接近的等價版本：{原解, 共軛翻轉 + 全域相位 φ_max} × {|平移| ≤ 4 px}，
  以複數場 L2 距離（FFT 互相關）選擇，選擇本身不回傳梯度。
- 首次修改既有程式（`src/config.py`、`src/losses.py`、`train.py`）。已測：關閉時 loss 與原版逐位元相同；
  等價解的振幅 / 相位 loss 為 0；原 loss 對同一批等價解給出大 loss。安裝前比對 md5 並備份。
- 評估一律用對齊後的分數。準則於結果出來前寫定，無預覽。

### 16.2 結果（網路本身，訓練分布，對齊後，3 seeds；收斂 0.34% / 0.31%，可比較）

| 指標 | `ideal_base` | `amb_base` | 差（z） |
|---|---|---|---|
| **FRC gain** | 0.2264 | 0.2465 | **+0.0201（2.7）** |
| 材料 MAE | 0.2890 | 0.2821 | −0.0070（−3.7） |
| 中心對稱度（對齊後輸出；真值 0.075） | 0.293 | **0.175** | −0.118（−31.3） |
| polygon / lattice / bandpass | 0.025 / 0.502 / 0.019 | 0.038 / 0.504 / 0.061 | +0.013 / +0.002 / +0.042 |

網路 + HIO 200 / 1000 次無差異；未見分布 0/4 → 1/4（fashion +0.23 dB，邊際）。

### 16.3 判定與結論

主判準 +0.0201 恰在 0.02 邊界（「部分成立」的下緣）；polygon、bandpass 未達 ≥ 0.10。

> **平凡歧異性是網路模糊的真實因素，但不是主因。** 拿掉後「對翻轉解取平均」的特徵（中心對稱度）大部分消失，
> 但重建品質只多 +0.02，polygon 與 bandpass 仍接近平庸基準。

圖：bandpass 中央的固定符號消失（換成均勻灰色紋理，仍無斑點結構）；角落的小亮方塊仍在。

## 十七、給了相位，網路仍學不會轉換：oracle 按原型與架構比較（v8，2026-09-23 / 24）

### 17.1 oracle 按原型分組（`oracle_proto.py`，不重新訓練）

兩種解釋：（甲）相位回復本身對前饋網路太難 → 給相位的 oracle 應在 polygon / bandpass 上表現好；
（乙）此 U-Net 連線性的反傅立葉轉換都學不好這類結構 → oracle 也失敗。準則事先寫定，無預覽。

| 條件 | 原型 | 相位未知 | **oracle** | 純 HIO 5000 |
|---|---|---|---|---|
| 現況 | polygon | 0.025 | **0.116** | 0.382 |
| 現況 | lattice | 0.502 | 0.603 | 0.646 |
| 現況 | bandpass | 0.019 | **0.045** | 0.734 |
| 理想 | polygon | 0.027 | **0.107** | 0.747 |
| 理想 | lattice | 0.507 | 0.594 | 0.634 |
| 理想 | bandpass | 0.027 | **0.038** | 0.708 |

依準則為「混合」：**bandpass 明確為乙**（理想條件下拿到完整繞射強度與真實相位，一次反轉換即可近乎完美，oracle 只有 0.038）；
polygon 形式上略過乙的門檻（0.107–0.116 對 0.10），實質上遠較接近乙。

**此 U-Net 未學會反傅立葉轉換本身，學到的是對週期結構有效的先驗。** §6.1「架構容量足夠」的證據僅來自 MNIST 這類平滑、低頻主導的物體。

### 17.2 架構比較的設計（oracle，理想條件）

三組訓練設定逐欄相同，只差 `arch`（程式驗證）：

| 組 | arch | 參數量 | 內容 |
|---|---|---|---|
| `ideal_bs0_ph1e5_oracle` | unet | 1.93 M | 已有 |
| `arch_fft_oracle` | fft | 1.94 M（+0.6%） | 偵測器端小網路（3 層卷積）→ **固定的反傅立葉轉換** → 原 U-Net |
| `arch_attn_oracle` | attn | 2.97 M（+54%） | 原 U-Net + 16×16、8×8 兩層各一個 self-attention 區塊（可學習的絕對位置編碼） |

fft：繞射振幅不經學習，直接由輸入反推 `sqrt(counts / scale)`（與 `forward_measure`、`hio.py` 同尺度）；
網路只估每個頻率的相位（K = 4 個假設）與 beamstop 內的振幅。已測：以真實相位代入，固定轉換還原物體的最大誤差 6e-7；
`arch=unet` 時模型與原版逐位元相同。

參考線：**直接反轉**（量測振幅 × 真實相位 → 反傅立葉轉換 → 套 support 方框，不學任何東西）。

> ⚠️ **透明聲明**：「直接反轉」不經網路，本地測試即為其小樣本預覽（約 0.70）。它只決定上限在哪，不影響各架構的判定門檻；兩種新架構無預覽。

### 17.3 結果（對齊後 FRC gain，3 seeds）

| 原型 | U-Net | **內建轉換（fft）** | attention | 直接反轉 | 純 HIO 5000 |
|---|---|---|---|---|---|
| 全部 | 0.287 | **0.766** | 0.292 | 0.765 | 0.700 |
| polygon | 0.107 | **0.792** | 0.117 | 0.792 | 0.747 |
| lattice | 0.594 | **0.726** | 0.598 | 0.726 | 0.634 |
| bandpass | 0.038 | **0.757** | 0.041 | 0.757 | 0.708 |

材料 MAE：U-Net 0.225、**fft 0.009**、attention 0.224、直接反轉 0.026、純 HIO 0.105。
推論（batch 64）：0.029 / 0.035 / 0.041 ms/sample。

判定：**fft 通過**（polygon / bandpass 皆 ≥ 0.50）；**attention 失敗**（皆 < 0.20，多 54% 參數，改善 < 0.01）。

### 17.4 解讀與限制

1. **瓶頸是「頻率空間 → 實空間」的轉換**：把轉換交給程式後，oracle 由 0.29 直接到物理上限（與直接反轉相同）；
   材料 MAE 更優於直接反轉（網路學會補 DC 像素與去雜訊）。
2. **attention 沒有學會轉換**：在本資料量與訓練預算下，「讓網路自己學全域轉換」不成立。
3. fft 三個 seed 到小數第四位相同：給定相位後任務近乎平凡。
4. ⚠️ **這是 oracle，成功在意料之中**。它證明「障礙在轉換、且內建轉換可解決」，**不代表相位未知時也會成功**（見 §十九）。

## 十八、dilation 從未生效的發現（v8，2026-09-24）

### 18.1 發現經過

安裝架構比較的程式時，md5 比對擋下了安裝：國網上的 `src/model.py` **等於交給 Claude 的版本去掉 dilation 支援**
（已在本地重建並以 md5 逐位元確認）。`config.py` 有 `dilation` 欄位，但國網上的 `DoubleConv` 不接受、`UNet` 也不讀取。
`Cfg.load` 只擋「不認識的欄位」，而 `dilation` 是認識的欄位 → **設定被靜默忽略，沒有任何錯誤訊息**。

### 18.2 查證（`check_dilation.py`）

同一份 `final.pt` 分別以「無 dilation」與「有 dilation」兩種結構評分（參數形狀相同，權重只在訓練時的結構下有意義）：

| run | config 的 dilation | metrics.json | 無 dilation | 有 dilation |
|---|---|---|---|---|
| `ovs64` × 3 | 1 | 0.142 / 0.145 / 0.133 | 相同 | 相同（對照） |
| `ovs96` × 3 | 2 | 0.123 / 0.124 / 0.125 | **重現** | −0.13 ~ −0.15 |
| `ovs128` × 3 | 2 | 0.121 / 0.110 / 0.112 | **重現** | −0.13 ~ −0.14 |
| `ctl_d2` × 3 | 2 | 0.144 / 0.143 / 0.134 | **重現** | −0.11 ~ −0.12 |
| `ctl_d3` × 3 | 3 | 0.145 / 0.146 / 0.134 | **重現** | −0.17 ~ −0.19 |

**12 個 run 全部確定：訓練與評估時 dilation 都沒有生效。**（本地以小模型驗證過此判別法可區分兩種結構。）

### 18.3 影響

| 原結論 | 狀態 |
|---|---|
| §12.2「以 dilation 對齊涵蓋率」 | ❌ 從未發生；`ovs96` / `ovs128` 的涵蓋率仍為 88.5% / 66.4% |
| §12.2「`ctl_d*` 相對 `ovs64` 無顯著差異 → 主實驗可解讀」 | ❌ 三者實為同一設定，無差異是必然 |
